## 1. 用户已经定下的（原话为准）

- 「感觉就是我们在分流代理里面新增一种除了socks5、http之外的一种新的类型就行吧，其余的逻辑都能复用」：Hysteria2 是「分流代理」里的**第三种代理类型**，不是新功能页。
- 「Hysteria2服务器本身，要不要走单位vpn，这个取决于服务器有没有在直连白名单啊」：连代理服务器走哪条路，照现有规则（分流直连名单或局域网里就走本地网络，否则经 Cisco；只开代理时一律走本地网络）。**不做自动直连**，也不加「一键加进直连」按钮。
- 「Hysteria2支持的一些参数……都能转化成统一的链接的形式？」：用户只粘一行链接。
- 「可以的，你准备下设计跟注意事项，然后交接给agy去开发落地」：本方案（随 App 带官方客户端）已同意。
- 界面上这条连接叫 **Cisco**，不叫 VPN（§69.20）。

## 2. 可行性结论（已和用户讲清）

- 本项目关掉 QUIC 的只有两处，都只针对**应用的网页流量**，碰不到 Hysteria2 客户端自己连服务器的 QUIC：
  - 出口保护：隧道里丢弃受保护 App 的 QUIC（§66）；
  - 走 HTTP 代理的网站：UDP 当场拒（§69.3）。
- 官方客户端的 SOCKS5 入口支持 TCP 与 UDP，正好接上现有的 SOCKS5 转发（含 UDP ASSOCIATE）。所以命中 Hysteria2 代理的网站连 HTTP/3 都能用。
- 真正的前提是 Hysteria2 的 UDP 能出去：
  - 只开代理时走本地网络；
  - 连着 Cisco 时，服务器要在分流直连里，否则进隧道，单位网络很可能挡 UDP；
  - 断线保护拦网时，直连名单里的地址照常放行（锚点的 `<ac_direct>` 表，§26），不在名单里就和其他流量一样被拦。

## 3. 用户体验

### 3.1 添加 / 编辑窗（Sources/App/ProxyPage.swift）
- 地址行接受 `hysteria2://` 与 `hy2://`。识别结果写在下面一行（绿：识别成功；橙：哪里不对），例如：
  `Hysteria2 · 203.0.113.10:443 · 端口跳跃 20000–50000 · 证书指纹已固定 · salamander 混淆 · 上 50 / 下 200 Mbps`
- 名称默认用链接里的 `#名称`，没有就用主机名。
- 链接里的密码（`auth`）和混淆密码（`obfs-password`）存钥匙串 vault（§69.19，名字见 §4.3），设置里不存明文；编辑时地址行不显示密码，只改别的不重输。
- 保存前照常检测（§69.8）；Hysteria2 的检测要分清原因（见 §5.4）。
- 连着 Cisco（自建连接）而服务器地址不在分流直连、也不在局域网时，在编辑窗下方给一行橙色提示（只提示，不改名单）：
  「Hysteria2 走 UDP，连着 Cisco 时会进单位网络，可能被挡；需要的话把服务器加进分流直连。」

### 3.2 面板与设置页
- 面板（设计 C）的分流代理一行不变：状态只说结果（"正常 · 42 ms" / "连不上"）。悬停与菜单里逐个代理写原因，Hysteria2 的原因用大白话：
  「UDP 出不去」「密码不对」「证书对不上」「服务器没回应」。不写协议细节（用户："不要绑死实现"）。
- 代理列表里类型标签显示 `Hysteria2`。

## 4. 链接与存储

### 4.1 链接格式
`hysteria2://[auth@]host[:ports]/?参数#名称`，`hy2://` 同义，默认端口 443。依据官方文档 URI-Scheme，源文件见 HyNetworks/hysteria-website：docs/docs/developers/URI-Scheme.md。

| 参数 | 含义 | 处理 |
|---|---|---|
| auth（userinfo） | 密码 | 必填；存 vault |
| host | 服务器名或 IPv4 | IPv6 字面量先不支持（分流整体只给 IPv4 答复，§69.4） |
| ports | `443` / `443,5000-6000` / `20000-50000` | 端口跳跃原样交给客户端 |
| `sni` | TLS 服务器名 | 缺省用 host；host 是 IP 且没给 sni 时，要求必须有 `pinSHA256` |
| `pinSHA256` | 证书指纹 | 支持；自签证书靠它 |
| `insecure=1` | 关闭证书校验 | **拒绝保存**，提示改用 `pinSHA256`（安全原则：不提供不校验证书的选项） |
| `obfs` / `obfs-password` | salamander / gecko | 支持；obfs-password 存 vault；gecko 需确认所带客户端版本支持 |
| `ech` | ECH 配置 | 原样透传 |
| `#名称` | 显示名 | 用作代理名称 |
| 我们加的 `upmbps` / `downmbps` | 带宽（Brutal） | 可选；不填用 BBR（官方默认） |
| 我们加的 `hop` | 端口跳跃间隔，秒，≥5 | 可选，默认 30 |

先不支持：自定义 CA 文件、客户端证书（mTLS）、`hysteria2+realm://`、QUIC 窗口与超时细调（用官方默认）。遇到这些，识别行写明「不支持：……」，不静默丢弃。

### 4.2 下发给后台服务的行（split_proxy 规则文本，§69.2）
- 新增：`proxy:<n> hysteria2 <host> <ports> <参数…>`，各字段百分号编码，参数为 `key=value`。auth 与 obfs-password 与现有 user/password 一样随行下发（XPC、不落盘）。
- 旧后台服务的 `Server::parse` 遇到未知类型返回 None，命中该代理的规则按「代理不存在」**拒绝连接**（§69.2 已有行为）：旧服务上这些网站打不开，不会改走直连或 Cisco。这条要有单测锁住。

### 4.3 钥匙串
- vault 里的名字：auth 用 `proxy@proxy-<id>`（与 SOCKS5/HTTP 密码同一个名字），混淆密码用 `proxy-obfs@proxy-<id>`。
- `passwordStamp` 照旧。删除代理时两个名字都删。
- 绝不进日志、诊断包、崩溃信息。DiagnosticsRedaction 要把 `hysteria2://` 链接整体打码。

## 5. 架构

### 5.1 谁跑客户端
- **后台服务**按规则表里的 Hysteria2 条目管理官方客户端进程，一个 Hysteria2 代理一个进程。监管逻辑（起停、退避重启、代次、哪个进程对应哪个代理、何时判死）写在 **Rust**（新模块，例如 `core/src/split_proxy/hysteria.rs`）。Swift 只做外壳（AGENTS 硬规则）。
- 客户端只开本机 SOCKS5：`listen: 127.0.0.1:<随机端口>`，带随机用户名和密码，别的本机程序拿不到。
- 规则表里第 n 个代理在服务内部改写成 `socks5 127.0.0.1 <port> <随机用户> <随机密码>`，再交给现有的 Routing 与转发。接收端、重定向、UDP ASSOCIATE、故障关闭全部复用，不另写数据通路。
- 生命周期：
  - 只在有重定向会话时运行：自建连接的分流会话或只开代理（§69.20 的 redirect 拥有方）。没有 Hysteria2 条目、代理开关关、会话停，就停进程。
  - 自建连接和只开代理之间交接（§69.20 的 handover）时，客户端进程**可以保留**（规则没变就不重启），减少重连。
  - 进程意外退出：退避重启（1s、2s、5s…封顶 30s）。期间命中的网站连不上（故障关闭），面板写原因。
  - 后台服务启动时，结束上一次留下的客户端进程（参照 `endOwnProcesses` 结束遗留 openconnect 的做法）；reset-network.sh 与卸载同样要结束它。

### 5.2 权限与可执行文件（硬规则：root 只执行 root 私有、验过签名的副本）
- 二进制随 App 打包，安装后台服务时同 openconnect 一样复制到 root 私有位置（例如 `/Library/PrivilegedHelperTools/AlwaysConnect-hysteria`），用 App 的证书 `codesign --verify --strict` 验签后才执行。
- 客户端**不需要 root**，以非特权身份运行（例如 nobody，或专用账号，二选一后写进 DESIGN）。配置文件放在只有该身份可读的目录（0700），里面有密码，进程退出即删。若官方客户端能从标准输入读配置，优先走 stdin（不落盘）；需确认。
- 配置里服务器写**已解析好的 IPv4**，`sni` 写原主机名（`tls.sni`）。这样客户端不用自己查 DNS，也不会绕回我们的转发器。解析由服务用转发器的 `resolve_plain`（§69.3）完成：
  - 名字在分流直连里，照常先装直连路由，再返回地址；
  - 只开代理时问本地网络的 DNS。
  - 端口跳跃只换端口不换 IP，路由与 pf 放行按 IP，不受影响。

### 5.3 网速与"本机代理"
- 客户端在本机（127.0.0.1），现有计数会把它当 `Leg::Local`：代理流量同时出现在「代理」和「直连 / Cisco」里（§69.17 已知限制）。
- 对受管的 Hysteria2，服务知道服务器 IP，Leg 应按**服务器地址的路由**取（`Leg::of(server_ip)`），从对应那一栏扣掉，不重复算。QUIC 包头开销忽略不计，或写明是估算。

### 5.4 检测与失败原因
- 运行中：沿用转发结果做健康（§69.8 的 proxyHealth），另外读客户端的日志输出，把常见失败映射成原因：认证失败、证书 / 指纹不对、握手超时（多半 UDP 被挡）、服务器拒绝。映射表写成 Rust 纯函数并单测；客户端原文只进服务日志，且先打码。
- 保存前的检测（§69.8）：App 进程跑不了客户端。需要一个新 XPC 方法，让服务按候选配置起一个临时客户端，经它的 SOCKS5 试连规则里的网站，回报结果与原因。照规矩：只发给与本 App 同版本的服务（installedHelperMatchesBundle），App 侧 3 秒超时，检测本身可以更久，异步回报。
- 先确认官方客户端有没有现成的连通性检测子命令（如 ping / 一次性检测）；没有就用上面的临时客户端办法。
