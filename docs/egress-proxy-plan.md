# 出口保护覆盖代理链路：方案与交接（2026-11-27）

交给 agy 落地。先读 AGENTS.md、HANDOVER.md、DESIGN.md §六十六（出口保护）、§六十九（分流代理，尤其 69.1 优先级、69.20 只开代理、69.21 代理服务器不走 Cisco）、§七十（Hysteria2，尤其 70.7 fast open）。本文只写方案、决定与注意事项；落地后把结论写进 DESIGN 新章节 **§七十一**，本文件保留作交接记录。

## 0. 用户原话与已定的事

- 2026-11-27 用户问："现在出口保护针对走代理的链路，非cisco的 也支持吗？"——答：不支持。现在受保护网站一律留在 Cisco（§69.1 优先级第一位），Cisco 关着（只开代理）时出口保护整个不运行。
- 用户先说"先不做，因为代理的出口国家是明确"，又问"如果要做，好做吗？成本怎么样？"，随后决定："**去做吧，完整点儿，你只拍agy去落地**"。
- 不变的前提（都是用户定过的，不许改）：
  - 出口保护的含义（§66 开头，用户 2026-11-19）：防的是"带账号、带登录状态的请求从错的出口出去"；不带身份的检查请求碰到目标网站不算漏网。门禁在查过之前一直关着，带账号的请求永远排在检查之后，出口不对就发不出去。
  - 规则分组、预期国家、"查不到时怎么办"（`unverified`）、复查周期（`halfLife`）、拦截记录（最近 10 条）、"允许这个国家"——全部沿用 §66，不另起一套。
  - 代理服务器本身一律走本地网络，不经 Cisco（§69.21）。
  - 故障关闭：代理不通、检查失败、出口不对，受保护网站一律打不开，绝不改走别的路。
  - 界面先出几版样子给用户挑（用户"有洁癖"），定了再写界面代码。

## 1. 现状（落地前请自己再核对一遍代码）

- **选路**：`core/src/dns_forwarder.rs` 的 `resolve_with` 里，`self.proxy...filter(|_| !skip_proxy && !rules.protects_name(..))`，即受保护的名字从不交给代理；地址类代理规则同样跳过受保护的名字和地址。直连名单同理跳过受保护的。所以今天受保护网站只会走 Cisco。
- **Cisco 这条路的出口保护**（§66）：`core/src/egress_control.rs`（Rust：分组、缓存、判断、记录，`Controller`）+ `core/src/egress_gate.rs` / `alwaysconnect-gate`（隧道里的逐连接门禁）+ Swift `Sources/Helper/EgressProbe.swift`（经 `ac_oc_set_egress_probe_with_peer` 回调，用 Network.framework 发一次 HTTPS `GET /cdn-cgi/trace`，强制走隧道网卡）。
- **代理转发**（§69）：`core/src/split_proxy/relay.rs` 的 `serve()`（TCP）和 `datagram()`（UDP）是每条经代理连接的必经之处；`Routing::target()` 决定用哪个代理。
- **只开代理**（§69.20）：`core/src/proxy_only.rs` 的会话里没有出口保护；面板设计 C 里"分流直连 / 出口保护 / 断线保护"三行在 Cisco 关着时变灰，写着"这三项跟着 Cisco，连上后生效"。
- **Swift 检查**：`EgressProbe.exchange` 正式版只认 `.other` 类网卡（隧道），回环只在 `EGRESS_PROBE_TEST` 下可用。

## 2. 目标

受保护网站不管走哪条路——Cisco、某个代理、（只开代理时的）本地网络——都先查出口，对了才放行带账号的连接，不对就拦。用户在界面上能看到每组规则当前走哪条路、那条路查出来的出口。

## 3. 需要用户先定的三件事（agy 开工前用问题卡问，附推荐项）

**D1 受保护网站和代理规则同时命中时走哪条路**
- 推荐 A：**代理优先**。命中某个代理的规则就走那个代理，并在那个代理上检查出口；没命中代理才按现在的走 Cisco。用户不用多配任何东西，想让 openai 走新加坡的 Hysteria2，就在那个代理的规则里写上 openai。
- 备选 B：每组出口保护规则自己选"经 Cisco / 经代理 X / 跟随分流规则"。更灵活，界面更复杂。

**D2 Cisco 关着（只开代理）时，没被代理接走的受保护网站怎么办**
- 推荐：也经本项目转发，直接从本地网络出去，**照样检查出口**，不对就拦。例如 openai 要求 SG，人在国内时本地出口是 CN，会被拦；人在新加坡时能用。这才是"完整"的保护。
- 备选：直接拦（打不开），或者不保护（维持现状）。

**D3 现有用户的行为变化**
- 现在 Cisco 关着时受保护网站不受保护；按 D2 推荐，升级后这些网站在只开代理时可能被拦。推荐：沿用出口保护原来的总开关和每组开关，不新加开关；出口保护页和面板上写清"Cisco 关着时也保护"。是否需要单独的开关，让用户定。

## 4. 方案

### 4.1 选路（Rust，`dns_forwarder` + `split_proxy`）
- 去掉"受保护的名字不交给代理"的排除，改为：受保护的名字**命中代理规则**时交给那个代理（D1-A），给本项目的地址，名字交代理解析。按地址命中的代理规则同理。
- 只开代理时（D2）：受保护的名字没命中任何代理，也给本项目的地址，转发层用一条"本地直出"的路径（不经代理，直接连目标）。可以把它当成转发层里的一个内部路径，比如 `Path::Local`，和代理 `Path::Proxy(n)` 并列。
- Cisco 连着且没命中代理：维持现状，走 Cisco，由 §66 的隧道闸门管。
- 直连名单永远不接走受保护的网站（现状不变）。

### 4.2 检查（Rust 决定，Swift 只发请求）
- 复用 `egress_control` 的 `Controller` 和缓存，但缓存键要加上**路径**：同一组在 Cisco、代理 1、代理 2、本地直出上的结果互不相干。`BlockRecord`、`GroupStatus` 带上路径。
- 经代理发检查请求（关键，推荐做法）：
  - Rust 在 127.0.0.1 上开一个**一次性的临时端口**，只接受一个连接，接上后经指定的代理（`open_through`，Hysteria2 用它的本地 SOCKS5）连到 `网站:443`，两边对接；
  - 然后让 Swift 照旧发 `ProbeRequest`：`host` = 网站名（TLS 的 SNI 和证书校验照旧按网站名做），`connect_ip` = 127.0.0.1，`port` = 那个临时端口，`interface` = `lo0`；
  - Swift `EgressProbe` 只改一处：`interface == "lo0"` 时用回环网卡（正式版现在只认隧道网卡）。其余 TLS、证书校验、读回应、解析 `/cdn-cgi/trace` 全部复用。
  - 本地直出路径同理，只是临时端口直接连目标，不经代理。
  - 这样检查走的就是这个代理的真实出口，证书照常校验，不需要 macOS 14 才有的代理设置 API（项目最低 macOS 13）。
- 注意 **Hysteria2 开了 fast open（§70.7）**：CONNECT 立即返回成功，不能拿它当"连上了"的证据；只认 `/cdn-cgi/trace` 的回应。
- 什么时候检查：路径第一次被用到（第一条连接到来）、代理重启或规则变化、网络变化、按 `halfLife` 定时复查（复用 §66.31 的预取/刷新逻辑）。同一组同一路径同时只跑一个检查，防止检查风暴。

### 4.3 门禁（Rust，`relay.rs`）
- `serve()`：拿到目标和路径后，如果目标是受保护的名字或地址：
  - 已验证且没过期 → 正常转发；
  - 未验证 / 检查中 → **不转发任何字节**，挂起这条连接等检查结果（上限几秒，可参考 §66 的等待上限），超时按 `unverified` 策略处理；
  - 出口不对 → 拒绝连接，写拦截记录、发通知（复用 §66 的记录与通知）。
- `datagram()`（UDP）：受保护网站的 UDP（QUIC）一律不转发，浏览器会改用 TCP。与 §66.5 隧道闸门丢弃受保护 QUIC 的做法一致。
- 检查请求自己的连接（经临时端口）不经过门禁。

### 4.4 只开代理的会话（Rust + Swift 外壳）
- `ProxyOnly` 里挂一个出口保护的 `Controller`（或者共用一个由后台服务持有的实例），出口保护规则随 `update_rules` 一起推。
- 检查用的 Swift 回调要在只开代理时也能用：新增 FFI（例如 `ac_proxy_only_set_egress_probe`），或者做成全局回调。新加的 XPC 方法照规矩：App 侧 3 秒超时回落，只发给版本匹配的后台服务。
- 面板与 `getSplitStatus` 的出口保护状态在只开代理时也要有值。

### 4.5 界面（先出样子，用户挑了再做）
- 出口保护页：每组显示"现在走哪条路"（Cisco / 代理名 / 本地网络）和"这条路最近一次查到的出口国家与时间"；拦截记录多一列"经哪条路"。
- 面板设计 C：出口保护那一行在 Cisco 关着、分流代理开着时不再变灰（它现在也管代理）；文案要改。
- 分流代理的编辑窗：规则里有网站同时受出口保护时，给一行灰色说明"这些网站经此代理时先检查出口"。
- 离屏渲染加示例数据，出几版给用户挑；颜色沿用现有约定（青色 = 出口保护）。

## 5. 不做的事
- 不检查没受保护的代理流量的出口。
- 不改 Cisco 那条路的隧道闸门（§66）。
- 代理服务器本身照旧走本地网络（§69.21）。
- 不新增下载源、不新增常驻进程。

## 6. 注意事项（踩坑预警）
1. **常驻逻辑在 Rust**：选路、门禁、缓存、复查时机都写在 `core/`；Swift 只有 `EgressProbe` 那一处网卡判断、FFI/XPC 外壳和界面。
2. **故障关闭**：检查前一个字节都不能转发出去；检查失败按 `unverified`；任何异常都是"打不开"，不是"放行"。
3. **不许把带账号的请求当检查**：检查只发 `GET /cdn-cgi/trace`（`egress_control::trace_request`），不带 Cookie。
4. **临时端口安全**：只绑 127.0.0.1、只接受一次连接、短超时、用完即关；只接受本后台服务进程自己的连接（可用 `owner` 模块核对对端进程，或接受后核对源端口是 Swift 那一侧发起的）。
5. **pf 只能经 NetworkGuard 写**：这个功能不应该需要新的 pf 规则；如果觉得需要，先停下来问。
6. **开销不劣化**：每组每条路径定时一次检查，平时每条连接只多一次查表；汇报改前改后的 `footprint` / CPU（AGENTS 硬规则）。
7. **隐私**：仓库零敏感信息；示例国家、网站用示例值；推送前按本地关键词清单扫描（见 AGENTS）。用户真实的代理地址、服务器域名不进仓库。
8. **Hysteria2 fast open**：CONNECT 成功不代表网站可达（见 4.2）。
9. **地址类规则**：受保护规则也可以是网段或 geoip，按地址命中时同样要走门禁；写测试覆盖。
10. **卸载与恢复网络**：如果新增了任何文件或偏好，同批加进 `uninstall.sh` 与 `uninstall-test.sh`。

## 7. 测试
- Rust 单测：选路优先级（受保护 + 代理命中 / 未命中；Cisco 连着 / 只开代理）；门禁状态机（未验证挂起、通过、出口不对拒绝、超时按 `unverified`、过期复查）；缓存按路径隔离；UDP 拒绝；临时端口只接一次。
- 转发层测试：用现有的假 SOCKS5（`split_proxy/tests.rs` 里的 `socks_proxy`）加一个回 `/cdn-cgi/trace` 的假站点；Rust 层把检查回调换成桩，返回预设的 trace 文本。
- 真实 Swift 检查：`EgressProbe` 的 `lo0` 分支用现有 `EGRESS_PROBE_TEST` 那套本地 HTTPS 测试服务器覆盖。
- CI root 检查：在 `core/examples/proxy-only-check.rs` 里加一段，只开代理 + 受保护网站经代理（Hysteria2 服务端 ACL 把名字指到本机回显，参见 §70.5 的做法），验证检查通过前不转发、通过后转发、出口不对时拒绝。
- 实测清单 `docs/mac-proof-checklist.md` 新增 L27 起：只开代理时受保护网站经 SG 代理可用；本地出口不对被拦；换代理后重新检查；Cisco 连着时受保护网站命中代理规则走代理并检查。
